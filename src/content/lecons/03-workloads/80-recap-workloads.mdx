Toute l'étape suit un seul fil : **la vie d'un pod**. Le workload décide comment il est recréé, le scheduler où il atterrit, le kubelet comment il démarre, vit et meurt. Chaque statut bizarre de `kubectl get pods` correspond à une case de ce schéma. Lance le pas à pas avec ▶, ou avance à ton rythme avec ›.

```mermaid
flowchart TD
  %% scene: Le bon workload :: Le chart rend des workloads : Deployment pour l'API, StatefulSet pour la base, DaemonSet pour les agents, Job pour la migration. Le contrôleur crée les pods. :: CH, CH>W, W
  %% scene: Le placement :: Le scheduler filtre selon les requests, les selectors, les affinités et les taints, puis note les nœuds restants. :: W>S, S, S>K, K
  %% scene: Aucun nœud ne convient :: `Pending`, et un `FailedScheduling` qui dit lequel coince : `Insufficient cpu`, `untolerated taint` ou `anti-affinity`. :: !S>P, !P
  %% scene: Les init containers :: Un par un, chacun doit sortir en 0. `Init:1/2` sans erreur : long, pas cassé. Lis `kubectl logs <pod> -c <init>`. :: K>I, I
  %% scene: Le démarrage :: Les principaux démarrent ensemble. Tant que la startup probe n'a pas réussi, liveness et readiness attendent. :: I>M, M
  %% scene: Prêt à servir :: La readiness réussit : le pod entre dans les endpoints du Service et reçoit du trafic. :: M>R, R, R>SVC, SVC
  %% scene: Readiness en échec :: Le pod sort des endpoints, `READY 0/1`, aucun redémarrage. Il revient quand il répond. :: !R, !R>SVC
  %% scene: Liveness ou mémoire :: Liveness en échec ou limit mémoire dépassée (`OOMKilled`) : le conteneur redémarre, de plus en plus tard. `CrashLoopBackOff`. :: M>L, L, !L>RS, !RS
  %% scene: Le nœud manque de mémoire :: Le kubelet expulse par ordre de QoS, BestEffort d'abord. Le pod `Evicted` est recréé ailleurs par son contrôleur. :: !K>EV, !EV, EV>W
  %% scene: Une mise à jour de cluster :: `kubectl drain` vide un nœud, pod par pod, si le PDB le permet. Un PDB trop strict bloque tout. :: DR, DR>T
  %% scene: L'arrêt propre :: Retrait des endpoints, `preStop`, `SIGTERM`, puis `SIGKILL` après le délai de grâce. :: T, T>SVC, SVC
  %% scene: Et la boucle repart :: Le contrôleur recrée le pod ailleurs ; en rolling update, `maxSurge` et `maxUnavailable` gardent la capacité. :: T>NW, NW
  CH["<b>Chart parapluie rendu</b><br/>manifestes de la plateforme"] --> W["<b>Workload</b><br/>Deployment, StatefulSet, Job…"]
  W -->|"crée les pods"| S["<b>Scheduler</b><br/>requests, affinités, taints"]
  S -->|"aucun nœud"| P["<b>Pending</b><br/>FailedScheduling"]
  S -->|"nodeName"| K["<b>kubelet du nœud</b><br/>monte les volumes"]
  K --> I["<b>Init containers</b><br/>un par un, Init:0/2"]
  K -->|"pression mémoire"| EV["<b>Evicted</b><br/>ordre de QoS"]
  I -->|"tous sortis en 0"| M["<b>Conteneurs principaux</b><br/>startupProbe d'abord"]
  M --> L["<b>livenessProbe, limits</b><br/>es-tu bloqué ?"]
  M --> R["<b>readinessProbe</b><br/>peux-tu servir ?"]
  L -->|"échec, OOMKilled"| RS["<b>Redémarrage</b><br/>BackOff, CrashLoopBackOff"]
  R -->|"succès"| SVC["<b>Endpoints du Service</b><br/>le trafic arrive"]
  EV -.->|"recréé ailleurs"| W
  SVC ---|"retiré d'abord"| T["<b>Arrêt</b><br/>preStop, SIGTERM, SIGKILL"]
  T ---|"provoqué par"| DR["<b>kubectl drain</b><br/>sous contrôle du PDB"]
  T -->|"le contrôleur recrée"| NW["<b>Nouveau pod</b><br/>maxSurge, maxUnavailable"]
```

<Retenir>
Le workload fixe comment un pod est recréé, le scheduler où il va, les probes s'il reçoit du trafic ou redémarre. Requests pour placer, limits pour plafonner. Un PDB protège des gestes volontaires, à condition de laisser passer au moins un pod.
