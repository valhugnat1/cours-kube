Sur ton PC, cluster kind `lab` de l'étape 0. Règle a minima ton shell pour ignorer les commandes précédées d'une espace (`setopt HIST_IGNORE_SPACE` en zsh).

## 1. Prépare le terrain

```bash
kubectl config current-context    # doit être kind-lab
kubectl create namespace lab6 && kubens lab6
```

## 2. Variable figée, fichier vivant

```bash
kubectl create configmap cfg --from-literal=GREETING=bonjour --from-literal=app.conf=mode=a
kubectl apply -f - <<'YAML'
apiVersion: apps/v1
kind: Deployment
metadata: { name: app }
spec:
  selector: { matchLabels: { app: app } }
  template:
    metadata: { labels: { app: app } }
    spec:
      containers:
        - name: app
          image: busybox
          command: ["sh", "-c", "while true; do echo \"$GREETING / $(cat /etc/app/app.conf)\"; sleep 5; done"]
          env: [{ name: GREETING, valueFrom: { configMapKeyRef: { name: cfg, key: GREETING } } }]
          volumeMounts: [{ name: c, mountPath: /etc/app }]
      volumes: [{ name: c, configMap: { name: cfg } }]
YAML
kubectl logs -f deploy/app
```

Dans un autre terminal, change les deux valeurs (`kubectl edit configmap cfg`). Le fichier suit en moins d'une minute, la variable jamais. `kubectl rollout restart deploy/app` : elle suit.

## 3. Un secret qui n'existe pas

```bash
kubectl run s --image=busybox --overrides='{"spec":{"containers":[{"name":"s","image":"busybox","command":["sleep","3600"],"env":[{"name":"X","valueFrom":{"secretKeyRef":{"name":"nexistepas","key":"x"}}}]}]}}'
kubectl get pod s
```

`CreateContainerConfigError` : c'est ce que produit un ExternalSecret pas encore synchronisé.

## 4. Un ServiceAccount limité

```bash
kubectl create serviceaccount reader
kubectl create role cm-reader --verb=get,list --resource=configmaps
kubectl create rolebinding reader-cm --role=cm-reader --serviceaccount=lab6:reader
kubectl auth can-i list configmaps --as=system:serviceaccount:lab6:reader   # yes
kubectl auth can-i get secrets --as=system:serviceaccount:lab6:reader       # no
kubectl auth can-i list pods -n default --as=system:serviceaccount:lab6:reader  # no
```

Le Role est namespacé : rien ailleurs, rien d'autre.

## 5. Le vigile

```bash
kubectl label namespace lab6 pod-security.kubernetes.io/enforce=restricted
kubectl rollout restart deploy/app
kubectl get deploy app
kubectl get events --sort-by=.lastTimestamp | tail -3
```

Le nouveau pod est refusé : les events listent les champs manquants (`runAsNonRoot`, `allowPrivilegeEscalation`, `capabilities`, `seccompProfile`). Ajoute-les au template du pod et réapplique : il démarre.

## 6. Nettoie

```bash
kubectl delete namespace lab6
```
